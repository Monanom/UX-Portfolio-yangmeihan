# Git 连接 Cloudflare Pages 设计

## 目标与边界

将当前本地静态作品集纳入私有 GitHub 仓库，并由新的 Cloudflare Pages 项目读取 Git 自动构建。先验证新的 `pages.dev` 地址，不改现有 Pages 项目、DNS 或 `yangmeihan.com`。后续切换域名须单独确认。

## 版本与文件范围

- 沿用 `网页作品集` 的独立 Git 历史。现有 `main` 比当前工作分支落后 24 次提交；在当前分支形成一次经过审查的发布提交后，让 `main` 快进到该提交，并推送到 GitHub 私有仓库。
- 仓库保存页面源码、运行脚本、测试、构建脚本、页面实际需要的资源及用于重建这些资源的 JPG/PNG 原图和原视频。QA 截图、临时发布包和本地缓存不入库；不删除原图、不改写旧历史。用户已确认将约 51 MB 的项目原图存入私有仓库；发布脚本不会复制它们。
- 精确检查暂存列表及敏感信息，禁止 `git add -A`。现有其他工作文件保留在本地。

## 构建与发布

- GitHub 私有仓库使用用户已创建的 `Monanom/UX-Portfolio-yangmeihan`。Cloudflare 新建 Git 连接的 Pages 项目，生产分支设为 `main`；构建命令为 `node prepare-edgeone-release.mjs dist`，输出目录为 `dist`。这个脚本目前只复制 98 个经清单列出的网页文件。
- Cloudflare 项目仅发布到其新的 `pages.dev` 地址。预览通过后，是否把 `yangmeihan.com` 改指新项目，另行确认。
- 开通 GitHub 与 Cloudflare 集成时只授予所需仓库权限。若界面要求更广的授权范围，暂停并向用户说明。

## 验证与恢复

- 本地运行全部测试、构建，并逐项核对输出与源文件；保存提交哈希、构建日志和新项目预览地址。
- 预览检查首页标题、视频、手机布局、二维码、项目详情及资源加载。失败时修复并推送新提交；旧线上项目与域名保持不变，可随时继续使用。

## 取舍

新建 Pages 项目是因为现有项目采用直接上传，Cloudflare 不支持原地切换到原生 Git 集成。Git 自动部署需要私有仓库和 Cloudflare GitHub 应用访问权；这些是本流程的外部权限变更，执行前需用户确认。
